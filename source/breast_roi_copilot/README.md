# APEX 乳腺筛查 AI 决策与价值评估平台

APEX 是一个面向医疗运营与管理决策场景的 Streamlit MVP。平台将医院场景数据、PubMed 循证信息、人工确认机制和由原 R Shiny 模型迁移的确定性 ROI 公式串联起来，用于评估提升乳腺筛查覆盖率可能带来的临床与财务价值。

> 当前版本仅用于产品演示、情景分析和方法验证，不构成医疗建议、临床预测或财务承诺。

## 一句话产品介绍

一个将医院数据接入、循证参数补充、人工确认、确定性 ROI 仿真、敏感性分析和 AI 管理层报告连接成闭环的乳腺筛查决策辅助平台。

## 患者陪伴助手（C 端 MVP）

应用顶部可在“机构决策平台”和“患者陪伴助手”之间切换。患者端与原有 ROI 工作流隔离，用于脱敏或模拟病例的资料整理与照护导航：

- 从文字型 PDF、DOCX、TXT 提取内容；扫描件、照片和原始医学影像暂不支持。
- 使用严格结构化输出整理诊断、用药、复诊和检查事实，并保留文件、页码及原文引用。
- 所有事实默认待确认；只有患者确认后的医嘱和安排才能进入照护报告及任务清单。
- 基于经过审核的患者知识库回答问题，并展示真实来源；证据不足、改药或治疗决策问题会拒答或提示联系治疗团队。
- 患者资料与任务状态只存在当前 Streamlit 会话，不写入数据库。

患者端默认使用 `gpt-5.6-sol`。实时分析需要在本地 Secrets 或部署环境中配置：

```toml
PATIENT_OPENAI_API_KEY = "你的 OpenAI API Key"
PATIENT_OPENAI_MODEL = "gpt-5.6-sol"
```

未配置患者端 API Key 时，可通过“加载模拟病例”体验完整的确认、报告、任务和知识问答流程。

## 解决什么问题

医疗机构在评估乳腺筛查扩容方案时，往往面临以下问题：

- 医院人群数据、筛查参数、医学证据和成本数据分散，难以形成统一口径。
- 传统测算依赖人工整理表格和反复套用公式，效率低且难以追溯。
- 管理层不仅需要一个 ROI 数字，还需要知道数字来自哪里、受哪些假设影响。
- 大模型能够处理文本和生成报告，但容易产生幻觉，不适合直接承担医疗 ROI 计算。

APEX 的设计思路是：让 AI 负责理解、检索、归纳和表达；让规则与确定性模型负责数据校验和数学计算；让用户负责确认关键假设和最终决策。

## 3 分钟体验流程

推荐从首页的“AI 决策助手”开始体验：

1. **上传医院数据**：在“数据接入 → 上传与检查”中上传示例 CSV，或使用内置合成数据。
2. **检查数据质量**：系统校验字段、日期、年龄范围和重复记录，并展示派生字段的计算来源。
3. **描述目标场景**：例如“希望将 40–74 岁女性 DBT 筛查率提升至 70%”。
4. **补充缺失参数**：系统优先使用医院数据；缺失的检出率、召回率等参数可通过 PubMed 证据或明确标注的演示假设补充。
5. **人工确认参数**：AI 建议不会自动写入 ROI，用户确认后才进入计算。
6. **查看决策结果**：平台调用确定性 ROI 模型，展示新增筛查、检出病例、项目成本、净节约与 ROI。
7. **查看敏感性分析**：比较保守、基准和积极情景，并识别最需要核实的关键参数。
8. **生成管理层报告**：AI 基于已锁定的计算结果撰写结构化草稿，数字与引用需通过本地校验。

## 核心功能

| 模块 | 核心能力 | 用户价值 |
|---|---|---|
| AI 决策助手 | 将医院场景自然语言解析为结构化参数，并串联完整工作流 | 降低专业工具的使用门槛 |
| 数据接入 | CSV 上传、字段校验、日期计算、去标识化和数据质量提示 | 让输入数据可用、可解释、可追溯 |
| 证据与参数 | 调用 NCBI PubMed 接口检索真实文献，提取候选参数并保留 PMID | 为缺失参数提供可核验依据 |
| 人工确认 | 对证据、参数和报告保留确认步骤与来源记录 | 避免 AI 自动修改业务模型 |
| 风险优先级 | 对合成人群进行排序，比较随机外展与风险优先外展 | 演示有限外展资源如何优先分配 |
| ROI 仿真 | 复用原 R Shiny 模型逻辑，计算临床和财务结果 | 快速比较筛查覆盖率提升方案 |
| 敏感性分析 | 对关键假设进行透明、可复现的压力测试 | 识别最影响决策的参数 |
| 管理层报告 | 将已验证的模型输出整理为摘要、分析和下一步建议 | 帮助非技术受众理解结果 |

## AI、规则模型与人工的分工

| 角色 | 负责什么 | 明确不做什么 |
|---|---|---|
| AI | 理解自然语言、生成检索式、总结摘要、提出参数候选、撰写报告草稿 | 不计算 ROI，不虚构 PMID，不自动修改确认参数，不作医疗决策 |
| 规则与确定性模型 | 数据校验、派生字段计算、证据引用校验、ROI 计算、敏感性分析 | 不理解开放式业务意图，不代替临床判断 |
| 人工 | 确认医院场景、选择证据、批准参数、解释适用性、批准最终报告 | 不需要手工重复执行整套计算 |

这一分工体现了平台的核心治理原则：**AI 提建议，模型做计算，人作最终确认**。

## ROI 计算与敏感性分析

### 核心计算逻辑

Python 版本保留原 R Shiny 模型的主要计算口径，页面展示层不承担数学计算。核心关系包括：

- 新增筛查人数 = 目标人群规模 × max（目标筛查率 − 当前筛查率，0）
- 检出病例数 = 新增筛查人数 × 癌症检出率 ÷ 1,000 × 年龄调整系数
- 召回人数 = 新增筛查人数 × 召回率
- 完成随访人数 = 召回人数 × 随访完成率
- 避免治疗成本 = 检出病例数 × 单病例分期改善节约
- 项目总成本 = 筛查成本 + 召回随访成本
- 净节约 = 避免治疗成本 − 项目总成本
- ROI = 净节约 ÷ 项目总成本

模型中的发病率、分期分布、治疗成本、检出率、召回率和分期改善比例均属于需要确认的数据或假设。页面输出是情景测算，不代表真实世界一定发生。

### 什么是敏感性分析

敏感性分析不是让 AI 预测未来，而是回答：“如果关键假设没有想象中准确，结果会变化多少？”

当前版本采用透明的压力测试方式：

- **单因素敏感性分析**：每次只将一个关键参数上下调整 20%，其他参数保持不变，再重新运行同一套 ROI 公式。
- **保守情景**：降低检出率和分期改善效果，同时提高筛查及随访成本。
- **基准情景**：使用用户已经确认的参数。
- **积极情景**：提高检出率和分期改善效果，同时降低筛查及随访成本。

系统根据净节约波动范围对参数排序。波动越大，说明该参数越影响决策，也越值得优先获取医院真实数据或更高质量证据。

这些情景是可复现的业务压力测试，不是置信区间，也不是对未来结果发生概率的预测。

## 当前模型范围

- 目标人群：40–74 岁女性。
- 筛查方式：DBT / 3D mammography（数字乳腺断层合成摄影）。
- 当前版本不将 Digital Mammography、MRI 或超声直接混入同一参数体系。
- 若未来支持新的筛查方式，需要建立独立、可追溯的参数配置和验证测试。
- ROI 内核为确定性模型，不是机器学习预测模型。
- 风险优先级和模型性能页面使用合成数据进行产品演示，不代表医院真实评估结果。

## 数据与隐私说明

- 仓库提供的数据为明确标注的合成测试数据，不包含真实患者信息。
- 上传文件仅保留在当前 Streamlit 会话中，MVP 不会将患者级数据写入数据库。
- 当前版本不连接医院 EHR、HDR 或生产数据仓库。
- 患者 ID 可在下游使用前替换为本地单向哈希值。
- OpenAI API Key 只能保存在本地 `.streamlit/secrets.toml` 或 Streamlit Cloud Secrets 中，禁止提交到 GitHub。
- 在接入真实医院数据前，仍需补充身份认证、访问控制、审计日志、加密、数据保留策略和合规评审。

## 已知局限

- 当前为面试与产品验证用途的 MVP，不是经过医疗器械认证的临床系统。
- 未接入真实医院 EHR/HDR，患者级流程和风险排序主要使用合成数据演示。
- PubMed 摘要不一定包含可直接迁移的数值参数；缺乏证据时系统应明确显示“证据不足”。
- 文献结果的目标人群、研究设计和医疗环境可能与目标医院不同，不能仅凭单篇摘要替换本地参数。
- 当前 ROI 模型没有概率分布或置信区间，敏感性分析仅表示假设变化对结果的影响。
- 分期改善、生命挽救和治疗成本避免等结果高度依赖输入假设，不能解释为已实现收益或因果结论。
- 实时 AI 输出可能因模型版本变化而不同，因此必须经过数字、引用和人工校验。
- 当前未实现生产级用户权限、数据库持久化、审计平台和运营监控。

### 设计原则

1. ROI 数学计算与页面展示解耦。
2. LLM 不参与 ROI 数学计算。
3. AI 输出中的数字必须能追溯到已锁定的模型结果。
4. PMID 必须存在于本次检索或批准证据中。
5. AI 推荐参数必须经人工确认后才能应用。
6. 无 API Key 或外部接口失败时，核心确定性模型仍可使用。
