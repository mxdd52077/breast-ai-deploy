## 模块一：简历直抄版（适合直接填入简历）

### 【版本 A：全栈开发 / AI 应用开发工程师】

**项目名称**：APEX 珊瑚红乳腺 AI 全周期照护与价值决策平台  
**项目角色**：全栈开发负责人 / AI 算法与工程落地  
**技术栈**：  
- **前端**：React 18、TypeScript、Vite、Vanilla CSS（PC 三栏响应式 / 移动端自适应）  
- **后端**：Python 3.12、FastAPI、SQLAlchemy、Pydantic v2、NDJSON 流式长任务协议  
- **AI / 检索**：LangGraph、Kimi K3 (Moonshot)、pgvector (384 维向量)、百度 PaddleOCR-VL 异步版面分析、NCBI PubMed E-utilities  
- **存储与安全**：PostgreSQL (Supabase) / SQLite、S3 兼容私有对象存储、HttpOnly Cookie、CSRF Token、乐观锁版本控制  

**项目描述**：  
针对乳腺癌患者病历分散难以管理、随访易脱落，以及医疗机构在筛查扩容时卫生经济学价值（ROI）测算复杂、缺乏循证依据的行业痛点，主导研发了集“C 端患者全周期照护”与“B 端机构筛查 ROI 决策分析”于一体的医疗级数字平台。

**核心职责与技术产出**：
1. **架构与全栈交付**：主导系统前后端架构设计，基于 React + TypeScript + FastAPI 搭建 PC 优先且适配移动端的响应式平台；制定严格的 Pydantic 强类型数据契约与多租户权限隔离体系。
2. **多模态病历解析与可溯源事实链**：集成百度 PaddleOCR-VL 异步解析管道，实现扫描件、PDF、手写检验单的高精度结构化；研发原文坐标级高亮对照机制，确保抽取出的诊断、用药、复查事实 100% 可回溯原件。
3. **确定性防幻觉与卫生经济学仿真**：确立**“AI提建议，模型做计算，人作最终确认”**核心原则。摒弃 LLM 直接计算的幻觉风险，采用 Python 纯函数构建确定性 ROI 仿真与敏感性龙卷风图；自研报告校验引擎，对大模型生成的管理层报告进行数值与 PMID 硬校验，杜绝伪造。
4. **流式问答与向量检索**：基于 LangGraph 与 Kimi K3 搭建随访问答 Agent，配合 pgvector 本地 384 维余弦检索，实现患者个人已确认事实与公共医学指南的分流引用；通过 NDJSON 流式协议降低长链路等待延迟。
5. **高可靠任务与状态机**：设计事实/任务版本乐观锁（Version Lock），实现撤回重审时历史任务完成状态无损保留；设置文件 SHA-256 去重与失败重试队列，大幅降低 OCR 接口调用成本。

## 模块四：面试深挖与高频追问准备 (Q&A)

### Q1：在医疗和大模型场景下，如何解决大模型的“计算幻觉”和“胡言乱语”？
> **回答要点**：
> 1. **架构分工原则**：我们从一开始就贯彻了“**AI 提建议，模型做计算，人作最终确认**”的设计哲学。我们坚决不把加减乘除、卫生经济学 ROI、发病率等数学运算交给大模型，而是通过后端纯 Python 确定性函数闭环计算，保证数学计算 100% 确定、可复现。
> 2. **报告生成双向硬校验**：在输出管理层报告时，系统先在后端锁定计算数据快照，大模型仅负责润色叙述；生成后，后端自研正则校验器扫描全文，若报告中的金额、百分比或 PMID 文献号与快照不符，强制拦截报错并拒绝落库。
> 3. **患者问答白名单**：通过 LangGraph 分流，个人病历只允许引用 `review_status=confirmed` 的向量切片；遇到调药、手术等高危操作强制触发免责拒答。

### Q2：医疗病历的 OCR 解析为什么选择异步长任务？如何保证可靠性与一致性？
> **回答要点**：
> 1. **长耗时与解耦**：医疗扫描 PDF 或多页照片往往包含表格和几十页文字，同步 HTTP 会导致网关超时（如 Vercel 300s / Nginx 60s 超时）。因此设计了 `Document` + `Job` 异步状态机，前端通过后台轮询或 NDJSON 监听状态，用户切页不中断。
> 2. **文件去重与成本控制**：在文件落盘前计算 SHA-256，同租户重复上传秒级复用旧解析，避免重复支付 OCR API 费用。
> 3. **版本控制（乐观锁）**：事实修改携带 `version`，防止用户在核对页面多端并发覆写；若事实被撤回，关联的日历任务进入冻结态；若重新确认，历史已完成状态自动复原。

### Q3：为什么不把整个项目直接做成微信小程序或纯移动端，而是“PC 优先、手机自适应”？
> **回答要点**：
> 1. **重度核对与阅读场景**：医疗病历和检验单通常尺寸大、信息密度高。桌面端 1280px/1440px 宽度允许实现“左侧原件 PDF/高清图 + 右侧提取事项”的双栏并排高亮对照，极大降低患者核对眼动成本；
> 2. **B 端管理决策需求**：B 端的医院管理者、科室主任需要在大屏幕上查看多情景敏感性分析表、龙卷风图以及管理层报告，移动端无法满足严肃决策的视觉沉浸感。
> 3. **手机自适应补全轻量操作**：针对患者日常“今日吃药”、“查看复查时间”、“随身向医生展示档案”等场景，流式降级为底部 4Tab 移动端界面，兼顾专业核对与便携随访。
