# APEX 患者优先产品与UI优化方案

## 产品主线

患者进来应当迅速知道“我有哪些已确认安排、哪些信息需要核对、下一步在哪里”。保留年轻活泼的外观，但事实、日期和来源必须比插画更突出。

首版为中国大陆患者使用的手机网页，电脑提供适配；机构端继续存在但采用独立入口。包含照片/扫描件资料整理、持续档案、逐条确认、今日照护和有依据问答。不包含家属协作、短信/微信主动提醒、医院系统对接或诊疗决策。

## 页面和关键行为

| 页面 | 核心内容 | 主要动作 |
|---|---|---|
| 首页 | 今日已确认安排、下一次复诊、待核对数量、最近资料处理状态 | 查看安排、继续核对、添加资料 |
| 档案 | 按时间的资料列表、事实分类、来源、版本与处理状态 | 上传、查看原件、核对、查看历史 |
| 照护 | 默认日程列表，可切换日历；分组为今日、待办、历史 | 完成/跳过、查看关联事实，修正状态 |
| 问答 | 最近问答、建议问题、回答依据与更新日期 | 提问、打开引用、记录就诊问题 |
| 个人入口 | 账户、资料处理说明、隐私和删除请求 | 退出、查看/删除自己的资料 |

“照护报告”并入档案的摘要视图及就诊准备入口，避免占用一级导航。患者界面不展示密钥、模型型号、token或技术开关。

### 从资料到计划

1. 选择文件或拍照，展示格式、单文件与整批限制；确认上传前可移除文件。
2. 显示“上传中/识别中/待核对/部分失败/失败”各自的进度和可操作项。切页后作业继续，可返回查看。
3. 已有档案保持可用。新资料形成独立候选批次，不在上传动作时替换当前档案。
4. 核对卡呈现提取值、原文高亮、文件名及真实定位。手机上下对照，电脑左右对照。
5. 操作包括“确认并继续”“有误，暂不加入”；用户纠正与文档原文分开存储，不伪造来源。日期缺失/冲突提供专门待核对提示。
6. 保存成功后更新确认数量和相关未来任务；网络失败保留当前输入，重试不重复创建任务。
7. 历史确认、来源版本和已完成任务保留。撤回事实确认时，展示受影响的未来安排并停止其执行资格。

### 首页状态的区别

- 尚未上传：显示“从第一份资料开始”，不显示伪造健康指标或治疗阶段。
- 资料正在识别：显示处理状态与返回入口，不阻止查看旧档案。
- 尚有事实待确认：突出数量和继续位置。
- 没有已确认安排：明确写“暂无已确认安排”，不能表示患者今天无需照护。
- 今日任务完成：仅在确有已确认任务且全部完成时显示完成状态；避免“棒棒的”等幼态化文案。
- 服务异常：说明资料保存/处理到哪一步，给出针对该步骤的重试。

## 三套设计方向

六张图由内置 imagegen 独立生成，每套为手机首页与资料核对页。完整提示词与生成来源保存在 `designs/prompts.json`，原始PNG未被后处理修改。虚构患者小安、虚构复诊记录和2026-09-12 09:00作为统一比较内容。

| 方向 | 主视觉 | 适合的表达 | 定稿应调整 |
|---|---|---|---|
| A 活力珊瑚 | 奶油白、珊瑚橙、杏桃、柔和植物 | 温暖、有活力的陪伴感 | 缩小首屏插画；区分品牌橙与状态警示色；加深浅底文字 |
| B 清新薄荷 | 薄荷绿、天蓝、明黄、深绿文字 | 活泼同时保留信息清晰度 | 蓝色按钮对比度、来源正文大小和按钮主次需统一 |
| C 灵动丁香 | 丁香紫、浅粉、电光蓝、深紫文字 | 更鲜明的年轻品牌辨识度 | 标题字形、图标风格与浅粉按钮需统一 |

这些是风格选型图，尚未做像素级可访问性认证或完整交互验收。图片中少量自动补出的问候/夸赞文案不进入最终产品。三个方向保留相同关键字段，装饰、具体换行和图标有生成差异。

打开 `designs/index.html` 可以切换首页/核对页、六张并排和点击放大。选择A/B/C或说明组合偏好后，下一轮按选定方向生成完整组件规范和页面细化稿。

## 定稿时采用的布局规则

- 手机以390px逻辑宽度为主，覆盖360、390、430px；电脑覆盖1280和1440px。正文优先16–18px，触控区域至少44px。
- 底部四项导航固定且留出安全区；核对页操作区不遮挡来源正文，长内容滚动时仍能访问操作。
- 欢迎区控制在紧凑区域，今日状态与下一步入口优先；插画主要用于欢迎、空态与完成态。
- 状态采用文字、图标与颜色组合；不以红绿颜色单独区分待确认/已确认。
- 普通文字对比度目标至少4.5:1，大字和必要控件边界至少3:1；选型图的浅色按钮在实现前调整。
- 无必要动画；尊重减少动态效果设置；加载时不挤压已读内容。
- 知识问答每条有依据回答保存来源和版本；拒答、服务失败、知识不足分别表达。

## 机构端同步优化

机构端围绕单个决策项目工作，不将所有功能平铺成多级工具菜单。

| 步骤 | 优化 |
|---|---|
| 数据检查 | 上传后给出通过项、需修复项、缺失参数以及直达操作；派生值清楚标明规则 |
| 参数核对 | 参数值、单位、来源、人群适用性、批准者与版本同时可查看；不让文献摘要直接变成批准参数 |
| 方案比较 | 基准与目标对照，展示成本、收益、关键假设和敏感性；结果绑定输入快照 |
| 报告 | 显示生成/待审核/已批准状态；图表数字链接至计算指标及假设，不隐藏失败回退 |
| 外展 | 展示数据来源与模拟假设，明确“规则模拟”与“实测结果”的差别 |

## 技术定稿输入与验收清单

无需等风格选择才能确认的技术原则：Python保持唯一计算内核；关键确认属于服务端操作；文件与资料分版本；异步识别不能丢失旧档案；任务记录不能被界面重绘重置；身份与存储按资源所有权隔离；OCR和模型链路采用核验后的境内服务。

选型后交付：明确框架及版本、提供商和地域、API与错误契约、核心表/状态流、异步作业与去重策略、迁移路径、部署拓扑、成本测算与分阶段工期。本轮没有宣称已经完成供应商核验或生产部署。

端到端验收包含：两账户访问隔离、同账户刷新/重登恢复、增量上传保留任务历史、重复文件不重复建任务、未知日期不自动落日历、冲突资料等待核对、扫描识别失败可恢复、已完成历史任务不显示逾期、确认撤回正确影响未来任务、聊天历史保留引用、删除后资源无法再次通过下载链接获取。
